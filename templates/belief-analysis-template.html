AUTHORING RULES (hidden text; leave in place, readers never see this): state the belief in positive form so the page headlines the supported claim. Every argument cell must be a complete, atomic proposition whose pro/con direction is evident from the cell alone. Never fill a score cell for an empty item. All scores stay [bracketed] until the ReasonRank engine computes them. Every table sorts by its rank key, descending; rows enter and rank only by the performance of their pro/con sub-arguments, never by editorial placement. Every row in every table is a scored relationship between this belief and the row's content; the software renders each table's top five rows and collapses the rest, so a row's position always traces to its score. Every evidence item must name what it bears on: a specific argument above, identified by its opening words, or this belief directly. Cells of the readout (What the numbers are made of) marked auto-derived are computed from the tables above it, never hand-picked. Arguments fail logically and go in the tree; evidence fails empirically and goes in the ledger. Spell words out: no abbreviated column headers, no cryptic placeholder tokens. Underscored [Bracketed_Tokens] are machine-replaceable substitution slots; leave the underscores so a script can find them, but keep every word readable. An Importance of [100%] is a default that means not yet differentiated, never a claim of maximal importance; differentiate it whenever the material supports doing so. Never ship an unverified link: check every href before publishing, and when a target page does not exist, use plain text rather than a dead link. When publishing an instance of this template, delete any section that would ship with nothing but blank cells; empty scaffolding is not analysis, and a short correct page beats a long blank one. When migrating an old page, preserve its filled content somewhere on the new page (People lists go to People on the Record; equivalent phrasings go to Similar Beliefs) rather than deleting it. INVITATION BLOCK: the boxed block under the H1 names an itch the reader already feels, asks the one question this page dissects, says why this is not a feed, and names one specific slot a newcomer can fill in five minutes; it never asks "what do you think," it invites the reader who disagrees, and it passes the reciprocity test (it names a behavior, never a tribe, so it would read the same to either side). ROW FORMULA: a row in the Argument Trees or the Evidence Ledger contributes sign x (2 x Truth - 1) x Confidence x Linkage x Importance x Uniqueness to the page above it. Truth is the row's own page score on 0 to 1; a claim nobody has argued sits at 0.50, so (2 x Truth - 1) is 0 and the row reads exactly 0, however famous the claim. Confidence is how much of the work behind that page has been done (0 to 1); a claim with no page contributes 0. Linkage, Importance and Uniqueness are each argued on a page of their own and read a labelled constant until then (Linkage 1, Importance 0.5, Uniqueness 1). Nothing on this page can be padded by listing more. 🔍 Argument Trees

Each argument is a belief with its own page, and its Score is that page’s truth score. A row contributes sign × (2 × Truth − 1) × Confidence × Linkage × Importance × Uniqueness, and that is the Impact column. A reason nobody has argued sits at Truth 0.50, so it reads exactly 0: listing a claim is worth nothing until it is argued. Confidence is how much of the work behind the argument’s page has been done; Uniqueness is whether this row makes a point no other row has made. Pro and con impacts sum to the Net Belief Score. A true-but-irrelevant argument scores high on truth and near zero on linkage, so it contributes nothing. Confirmed fallacy claims feed these factors too: a community-confirmed fallacy damages exactly the factor its type targets (relevance fallacies hit Linkage, formal fallacies hit the validity component of the Truth Score, evidence fallacies hit Evidence Quality) and is noted inline in the argument cell. A fallacy accusation that has not been confirmed changes nothing.

🎯 Decision Leverage

Which argument is worth settling next. Leverage is the points of conclusion score still at stake on one edge: Weight (how much of a change in that reason transmits to this conclusion: |linkage| × importance × uniqueness × 0.5depth) × Open (how much about that reason is still unresolved: evidence, linkage votes, opposition, scoring). High where an argument both carries the conclusion and rests on little. An upper bound on movement, not a forecast, direction is unknown, which is why the edge is worth investigating.

⚖ What Would Change the Answer

Every claim beneath this page held at false and then at true, one at a time, with the whole graph recomputed each time. If false and If true are where this page’s truth score lands; Move is how far apart they are. If settled is that same distance with the input’s confidence held at 1, which is what it would be worth once the work behind it is finished, so the gap between Move and If settled is the value of doing that work. An input that moves this page by less than 0.005 is inert: nothing anyone could learn about it changes the answer. This is one input at a time and finds single points of failure; it does not test several inputs moving together, which is how correlated assumptions actually fail.

📊 Evidence Ledger

Source type is what kind of thing the finding is, one of the eighteen the engine knows, and it sets where the finding’s truth starts before anyone argues it: statistics and data with the source cited, primary official record, randomized controlled trial, meta-analysis, observational study, historical trend, expert testimony with data, expert or social media claim, personal anecdote, common sense or logic, analogy, cultural norm, intuition, news report, survey or poll, eyewitness testimony, visual evidence, historical artifact (strongest first; the authoring notes list where each starts). Classify what the claim says, not the instrument that produced it. A finding with no source type named starts at 0.50 and pulls nothing either way. A row counts as sign × (2 × Truth − 1) × Confidence × Linkage × Importance × Uniqueness, the same rule as the arguments above, so a finding nobody has argued or sourced reads exactly 0. Standing is the verification lifecycle: Verified rows count in full, Unverified and Disputed at half, Falsified at nothing, Unrecorded (no status on record) in full. Standing is kept by the software only; where no lifecycle is recorded every row is Unrecorded and the column is left off. Format each item as: Finding (Producer, Year). Evidence is data that can fail empirically; a reason that can only fail logically is an argument and belongs in the tree above, not here. Every item must also name what it bears on: a specific argument above, identified by its opening words, or this belief directly. Evidence that bears on nothing contributes nothing, no matter how true it is.

⚖ Cost-Benefit Analysis

Every cost and benefit is itself a debatable claim with its own argument tree, and every row must survive three questions: compared to what, measured in what units, and how likely? Magnitude is an estimate in explicit units. Likelihood is computed from how that claim’s pro and con arguments score, never assigned by gut. Expected Value = Magnitude × Likelihood. Keep unlike categories (dollars, life-years, people-hours, freedom) in separate rows and subtotal only within a category; converting across categories is itself a debatable claim, so if you do it, state the conversion out loud (e.g., the value of a statistical life). How to read this page: nothing here is placed by editorial choice. The heading line’s truth score is the only number announced before the arguments; this readout comes last so that nothing tells you what to conclude before you have seen what it rests on. Every row in every table is itself a claim, and its Score is the ReasonRank performance of the pro/con sub-debate about that claim, computed recursively down to the evidence. Every table sorts by its rank key, best content first; the rank key is the rightmost score column: Impact for arguments and evidence, Expected Value for costs and benefits, Claim Strength for the Primary Conflict Pair, and Score everywhere else. In the ISE software each table shows its top five rows and collapses the rest until expanded. [Bracketed] numbers are hand-estimated placeholders until the engine ships, and score cells stay blank until real content exists to score. This wiki can’t sort tables live; the score columns are the data contract that lets the software sort, filter, and collapse every table automatically.

 

✍ Add to This Page

Every table above takes rows from readers. On the built site each of those tables carries a form like the one below: type one complete sentence, and as you type the page shows the claims already on the site that say the same thing, so a duplicate becomes a vote for the claim already here instead of a second page. Submitting opens a prefilled GitHub issue; a free GitHub account is the cost. A check on GitHub then either records your vote or opens a pull request that adds your rows for the maintainer to merge.

Submitting opens GitHub; you need a free account.

The forms a built page carries, one per table: a reason to agree and a reason to disagree (Argument Trees), a finding (Evidence Ledger), a prediction (Testable Predictions), a criterion (Objective Criteria), a cost or benefit (What Acting On This Would Cost and Gain), an interest (Interests, Not Positions) and a new belief (Related Beliefs). A table with nothing in it yet gets a form for its first row, and every row of What This Page Needs Right Now links to the form it goes in. The heading line carries Agree and Disagree vote links after the score, with the counts once anyone has voted. Votes are shown as what people think, next to what the analysis says, and never move a score: a claim nobody has argued is worth nothing however many people like it.
